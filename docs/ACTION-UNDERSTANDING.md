# 当前动作理解与主动式提议

2026-09-08，根据新的产品方向实现。此文描述当前行为，取代旧观测台 Diff 和单条 statement 的展示约定。

## 数据流

1. 采集原始事件、当前 AX 和截图。本轮不改前台切换校验，也不能把非原子采集宣称为同一毫秒快照。
2. 按已保存的触发规则筛选，默认新配置选择 Enter、空格和鼠标点击；已有自定义选择保持不变。未选中、失败、保护或错位记录只留在原始记录视图。
3. 本地原生进程用同一原始截图生成轮廓标注图与 Apple Vision OCR。不延迟再抓屏；蓝=焦点、橙=选区、绿=点击，不填色遮盖文字。区域不可用时不画框，OCR 失败明确返回 unavailable。
4. 理解模型接收中文系统 Prompt、动作提示、AX 树（含已采到的原始属性）、焦点 title、OCR 和标注图。只输出 `action_title` 与 `action_detail`，长度上限分别为 80 和 1200。AX/OCR 是可能失真的证据，按键本身不证明输入、提交或注册成功。
5. 理解可并发 1–20 条，默认 10。主列表只展示有有效新格式理解结果的事件；队列/原始记录保留状态和证据，理解中显示转圈，失败可重试。
6. 主 Agent 每次接收最多 20 条顺序摘要，每行是 `[YY-MM-DD HH:mm:ss.SSS] Action title / Action detail / Action-id`。快完成的后一个动作不能越过仍在理解的前一个动作。主 Agent 同时只处理一批，后续理解仍可继续；Agent 忙时不持续灌入新的批次。

## 工具与授权边界

- `get_ax_tree(action_id)`：读取该动作保存的 AX，不是当前桌面。
- `get_ocr_content(action_id)`：读取该动作理解输入中的 OCR 与置信度；缺失不伪造。
- `get_annotated_image(action_id)`：返回图片内容，不是仅返回路径。DSH 附件层可能将 PNG 标准化成 WebP，返回的 `sourceImageHash` 指原始理解输入图；主 Agent 需要支持视觉。
- `send_danmaku(text)`：显示一句主动提议。沿用已有不抢焦点、点击穿透、开关与限频；普通行为保持安静，不每条都回复。
- 外卖、日历、文件等业务写入不因弹幕而获得授权。当前外部写工具仍只产生 `not_executed` 提案；Web 搜索 provider 仍未接入，不能把“要不要查论文”说成已经检索完成。

## 可观测与修改

主界面三个视图是「已理解事件」「队列／原始记录」「主 Agent／工具」。原始事件永不冒充已经理解的事件。

点击记录打开侧栏。点击其他记录直接替换内容，侧栏不收起；点击空白区域或离开应用仍收起。前后 Diff 页面、前一记录查询和 Diff 实现已移除，不删除历史快照。图片放大默认适应当前窗口，调整窗口大小时重新计算，支持手动缩放和恢复适应窗口。

「AI 理解追踪」保存实际请求的中文系统 Prompt、完整文本输入、输入图 SHA256、模型、耗时、结构化结果和模型原始输出。请求失败同样保留追踪。理解图片按实际字节保存，侧栏无需重建标注。现阶段追踪/输入图沿用理解缓存的 24 小时清理策略，过期明确显示缺失，不重新拼造当时输入。

「设置 → 中文 Prompt 与理解并发」可编辑三种自定义 Prompt；默认文本集中在 `src/model/prompts.ts`，用户改动保存到 `prompts.json`，并发保存到 `ai-settings.json`，清空历史时均保留。理解 Prompt 修改只影响后续请求并参与缓存键；主/子 Agent Prompt 修改会重启运行时，保留会话。DSH 框架内置的协议说明不在此编辑。

## 本轮验证

- 54 项测试通过，涵盖输出校验、Prompt 缓存隔离、失败追踪、图片工具、多模态请求、并发上限、乱序完成按序投递、单批背压和原有存储/清空回归。
- 用明确标记为 FIXTURE 的 1600×1000 图片、本地模拟视觉及主 Agent 服务验证真实链路：原生标注/OCR → HTTP 理解 → 顺序轨迹 → DSH 调用 AX/OCR/图片工具 → 桌面弹幕 shown。
- 确认视觉请求的文本与输入 PNG 和侧栏追踪一致；主 Agent 收到的是实际图片块，经附件层标准化而非 JSON 文件引用。
- 实际指针点击验证跨卡片保持同一个侧栏 DOM；截图在大窗口和 1000×650 视口中保持比例、适应可用空间；检查了 Prompt/输入图标签和编辑保存。
- agent-browser 在此 Electron 环境仍误连空白页，诊断后以直接 CDP 完成隔离窗口验收。

这不是线上模型质量评测。真实应用 AX 覆盖率、前台变化导致的采集失败、OCR 误差、模型陈述准确率以及跨批次重启时的复杂重复投递仍需继续做真实场景验收。
