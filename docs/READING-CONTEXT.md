# 阅读 AX 取证

截图请求发出后，采集器在全窗口 AX 遍历之前执行局部阅读采样。原来的全窗口树仍受 20 层限制；局部树以当前选区或点击命中为锚点，拥有独立的 24 层、96 节点、650 ms 和 24,000 字符预算。它不会滚动页面、切换窗口、请求模型或读取其他应用。

`readingContext.selectedText` 优先保存 `AXSelectedText`，缺失时尝试同一元素的 `AXStringForRange`。插入光标的零长度范围不作为选区。范围使用 UTF-16 单位；实际采样时间、文本来源、独立阅读节点 ID 和截断状态一起保留。

`readingContext.context` 从最近的关联文本容器读取正文，不越过窗口、滚动区、整篇文档、列表或导航容器。正文优先以点击命中为锚点；选区独立保留，不能因为全屏焦点 `AXGroup` 暴露选区就把整窗内容当成正文。非文本点击容器及其祖先必须有可校验的局部范围，小于窗口面积的 60%；无点击时只允许文本控件提供正文。可读取应用已暴露但不在视口中的节点，`visibility: not_verified` 明确表示未验证它是否被用户看见。`related_subtree` 只是该局部子树；`text_control_range` 只是相应文本控件的字符范围，都不保证完整回复或聊天历史。未暴露、虚拟化未加载、通信失败和预算耗尽不会用推测补齐。

`fragments` 保存正文中的 UTF-16 起点、长度及源节点／属性，不重复保存正文。`reading:` 开头的 ID 属于独立局部遍历，不能当成全窗口树的 `n123` 节点引用。

`selectionAnchor` 表示选区取自焦点还是点击元素，`context.anchor` 单独表示正文锚点。`context.selectionRelation` 只有在选区元素被局部正文树访问时才标记 `same_subtree`；其他锚点中找到相同文本仅标记 `selected_text_found_in_context`。输入框选区与点击的另一段回复不匹配时保留两份证据，但标记 `unverified_different_anchors`，不声称它们属于同一回复。没有选区时为 `no_selection`。这些关系均不证明正文全部可见或用户已经读过。

每个元素读取正文前检查受保护类型。窗口身份不一致、截图失败或受保护内容命中时，阅读正文丢弃，只返回原因。截图与 AX 不是原子快照，分别记录时间，不将后来读取的内容宣称为按键瞬间已经显示。

自动验证使用合成 AX 数据源，覆盖选区、范围取文、深层节点、局部边界、隐私、窗口不一致与预算截断。它证明策略与字段契约，不代表 ChatGPT、飞书等真实应用必然暴露完整回复。
