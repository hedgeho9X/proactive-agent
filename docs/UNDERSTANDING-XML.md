# 屏幕理解的 XML 请求

## 证据投影和动态数据边界

`prompts/xml.ts` 将结构化数据序列化后转义 XML 文本字符，避免 AX、OCR、应用名称等内容闭合模板标签。标签用于区分来源，并非安全权限边界；屏幕文字始终不是指令。

`src/model/understanding-evidence.ts` 分别提取点击命中、焦点及选区，不以焦点代替点击。模型接收标准化文本节点和必要 URL／文档属性，不重复接收原始 `raw_nodes` 属性树；非焦点文字仍可保留用于理解场景，不对所有应用统一裁掉侧栏。原始记录不修改，完整属性仍可按 Action ID 查看。

不可用区域保留状态和原因，但不把其失效矩形作为可靠定位。没有 AX 时返回空节点集合，不伪造控件。

## 完整请求

`prompts/understanding.ts` 的 System Prompt 按职责、证据分工、输出契约、五种边界例子分区。硬件事件确定操作类型；点击优先看落点和命中控件，键盘优先看焦点；应用背景只说明用途。示例覆盖 Open、右键与焦点不一致、空格与输入法、Enter 未知发送结果、对象无法识别。

User Prompt 使用 `observation` 包裹硬件事件、app_info 和视觉证据，最后用 `task` 提出请求。原始落点只在 `hardware_event` 出现，不再在自然语言提示重复报坐标；窗口坐标系、图片像素尺寸、区域矩形和采样时间仍保留用于定位。未知鼠标按钮或手动快照不会被标成左键或按键。

动态文本全部通过 `xmlData` 转义，图片仍由 AI SDK 以独立 PNG 内容块发送。输出保持 `action_title` / `action_detail`，不做输出坐标的正则删除，避免掩盖模型未遵守规则的问题。

## 历史与设置

完整最终 Prompt 参与缓存哈希；更新模板不会复用旧模板结果。trace 保存实际发送的 XML 和原始模板变量，OCR 工具继续从独立字段读取，不解析 XML。旧 JSON／Markdown trace 不改写，不删除原始证据。

设置中保存的自定义 System Prompt 仍优先于默认文件；如果已有覆盖，需要在设置里保存新的规则正文才能采用新 System 规则。源码 User 模板会在重启新版后使用。此次不改变主 Agent Prompt、模型、并发、事件准入或 Dock 窗口归属。

验证包括动态闭标签与实体攻击、事件/修饰键保真、落点去重、点击与焦点分离、完整证据保留，以及实际 AI SDK HTTP 请求和 trace 一致性。均使用本机合成数据，未进行付费模型的同图 A/B；测试通过不等于已证实识别准确率提高。
