# AX 观测台 MVP

从侧边栏进入“AX 观测台”，刷新运行中应用并选择目标，点击延迟三秒采集后切回目标窗口。首次快照用于检查，第二次起自动与上一次对比。快照只留在面板内存，不进动作队列、数据库或模型；清空按钮同时移除两次快照。

焦点元素优先读取，随后遍历焦点窗口；焦点窗口不可读时从应用根继续。枚举节点支持的普通属性，分别保存已读取、无值、不支持、失败和预算耗尽状态。支持的动作和参数化属性只列名，不执行动作或盲目调用带参数接口。受保护输入内容及子树不读取。

预算为最多 800 节点、20 层、约三秒遍历时间；单次属性请求超时 30ms，文本最多 8000 字符，数组序列化最多 100 项。相关截断有标记。遍历预算不含截图时间，单次完整进程最多运行 15 秒。数组展示截断不等于子节点遍历只取前 100 项。各属性分时读取，快照不是原子状态。

截图独立调用 ScreenCaptureKit；能获取 AX 窗口 bounds 时匹配对应窗口，否则仅在目标进程恰有一个可见普通窗口时降级。歧义、权限问题或已发现受保护输入时不返回截图，并显示原因。尚未进行微信实际覆盖率评测，不能因 AX 失败推断反爬。

差异仅按同进程、同应用的路径和角色做候选匹配，临时 node ID 不作稳定身份。布局变化、焦点变化、窗口切换、应用 PID 复用或采集截断都可能造成误匹配；不能直接作为最终事实发送给 Agent。首次版本提供手动快照、属性检查、差异、截图及原始快照；持续通知时间线、可靠控件身份、文本范围读取和手动 AI 解读尚未实现。

建议用自建输入框或 TextEdit 逐项测试：中文输入、删除、粘贴、全选、提交和失焦。先比较屏幕实际变化和 AXValue/AXSelectedTextRange，再测试微信等应用，记录属性错误及覆盖差异。

本轮验证：类型检查、Swift/Electron 构建及 27 项测试通过。独立测试数据目录下的 Electron 实例通过页面交互完成选应用与手动采集，真实 AX 返回 33 节点并成功截图；属性显示无值 -25212 和失败 -25200 的差别。结构化坐标修复后再次采集返回 442 节点、725ms、截图成功。差异测试覆盖临时编号、字典键序、文本变化、读取失败和跨应用隔离。尚未实测微信、中文输入法全过程及系统授权被拒场景。
