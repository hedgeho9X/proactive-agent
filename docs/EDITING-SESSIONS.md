# 编辑采集与理解投递

原有点击、操作键截图和 AX 采集保持；原本过滤的普通字母、数字仍不逐键生成截图。新增 150ms 活动焦点 AX 采样，记录应用实际暴露的完整字符串与 UTF-16 选区，不从物理键码或输入法按键还原正文。不保证捕获每个中间字符状态。

已确认输入控件内的普通编辑键、Shift+Enter、光标移动与左键选区操作标记 editingActivity，原始采集记录继续保存，但 Understanding 路由返回 editing_activity_accumulating。快捷键、普通 Enter、Tab、Esc 和外部控件点击保持原链路；未知焦点不猜测为编辑。

焦点控件和所属 AX 窗口按 CFEqual 比较，进程启动时间参与身份判断；焦点、应用切换、读取失败、停止观察切断会话。安全输入和安全文本控件不读取正文。所有不可读情况均不能当作成功读到空字符串。

每个焦点会话在 ax-snapshots 下有一个草稿索引，AX 更新追加到该目录的 editing-revisions.jsonl，snapshot.json 是最新状态。正文不放入 meta.json 或 trigger。异步保存按草稿串行，修订倒序不能回写。

独立动作在进入异步采集前冻结最近已收到的同会话、同进程草稿，保存 editingEvidence。模型焦点证据中的 prior_editing_observation 和 AX 工具可读取这份副本。它是事件记录前的 AX 观察，不是发送成功证明，也不证明和点击目标是同一控件。当前草稿索引不进入历史理解检索，避免过去动作读取未来文本。

本次没有实现自动发送确认、失焦后自动调用模型或长时间草稿的周期总结。草稿关闭只保存原因；需要独立事件才触发已有理解。采集持续性、理解触发、最终主 Agent 投递是三个不同边界。

应用图标按 Bundle ID 从本机读取，主进程与渲染层去重缓存；不存在时显示名称首字。不改变应用归属判断，也不会修复 Dock 覆盖层误命中。
