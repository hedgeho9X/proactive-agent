# 事件触发取证的时间边界

点击改为 mouseDown，按键仍为 keyDown；单个事件带发生时间、阶段、坐标、进程来源和事件 ID。鼠标按下时前台可能尚未切换，监听器以 5ms 消息超时的命中查询优先定位目标进程；失败则明确标记前台回退。排除自身逻辑保留。

记录开始前预热独立 AX 采集进程。事件传入后使用持久管道请求，不再每条启动进程。截图请求与事件落盘并行。原生采集先让轻量窗口/焦点/命中查询发出截图请求，再与完整 AX 遍历并行运行。系统窗口枚举、AX 消息和 ScreenCaptureKit 自身仍有延迟。

timing 保存 eventAt、requestReceivedAt、axStartedAt/axCompletedAt、screenshotRequestedAt/screenshotCompletedAt，以及 nonAtomic=true。截图完成时间是 API 返回时间，不是操作系统保证的像素曝光时间；AX 树也有读取区间，不能描述成严格同一瞬间的原子快照。

蓝框只检查焦点控件身份和几何稳定，光标移动不会连带隐藏蓝框；橙框另行检查文字选区稳定；绿框标记事件坐标命中的同进程控件，身份或边界变化则显示不可用。每个区域保存自己的 nodeId、sampledAttributes 和采样时间。focusId 关联截图区域采样，较早树采样的焦点留在 treeFocusId；缺失的区域节点以截图采样时实际读取的属性补入，不在截图完成后冒充重新取得相同状态。

由于完整树和截图不可能无成本，当前仍只允许一个完整采集在途。忙时继续保存事件并标记 skipped_busy，不会排队补拍过时界面。窗口/前台变化、保护输入或采集失败继续显式报告。因此本版缩短了时差，但不保证高速连续操作每条都有完整证据。

验证：原生稳定性测试确认同一输入框的光标移动不会影响蓝框、会使旧选区失效；管道测试验证复用进程、请求关联和异常退出后重启。受控 AppKit 窗口经 CGEvent 到监听、常驻采集、历史存储全链路，按键/点击均成功；单次观测请求延迟分别约 128ms/67ms。点击样本蓝框对应输入文本区，绿框对应 Click target 按钮。上述为受控测试，不代表所有应用或性能分位数。

进一步将树的根窗口和焦点查询也移到截图请求同一阶段，避免早期的应用根降级树与稍后的窗口图混用。复测按键/点击请求延迟为 85ms/58ms，AX 读取分别为 34ms/20ms，绿色按钮区域与蓝色输入框区分正确。axRootScope 不同的快照禁止直接 Diff。上述时间来自两个受控样本，完整树仍不是事件时刻的原子快照。
